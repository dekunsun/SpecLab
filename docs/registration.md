# Registration: funnel v0.1 on MP-20 (written before the run)

Registered 2026-10-21 (UTC), before `scripts/run_funnel.py` and `scripts/retrospective.py` were run
on the full dataset. Only the 13 anchor structures listed under "What was looked at first" had
been evaluated by the dielectric estimator before this was written. Deviations are logged at the
bottom, dated, and never edited away.

## What is being tested

Spec `specs/high_k_gate_dielectric.yaml` v0.1 applied to all 45,229 MP-20 entries through four
hard-constraint stages (composition, stability, PBE band gap >= 3.4 eV, Clausius-Mossotti k >= 15)
and a tie-breaker score. The question is not "did we discover a material" (MP-20 contains only
known Materials Project entries). It is whether a spec written in material-level proxies, with
the stated margins, recovers the materials the field already uses and rejects the ones it
already rejected for the stated reason.

## What was looked at first

Clausius-Mossotti estimates on 13 anchors, run once to check the estimator was not broken:
MgO 8.8 (exp 9.8), SiO2 4.1 (4.5), Al2O3 9.1 (9-10), ZrO2 15.4 (20-25), HfO2 m 20.8 (16-25),
HfO2 o-Pca21 29.2, La2O3 34.1 (27-30), LaAlO3 119.4 (24: divergent, x = 0.975), HfSiO4 11.2 (11),
TiO2 29.8, SrTiO3 28.1 (300: divergent), Ta2O5 47.4, LaLuO3 27.8. This fixed two things in the
code before registration: the divergence cut-off x >= 0.98 and the k cap at 60 inside the score.
Nothing else about the funnel was tuned on these.

One run. The funnel is deterministic, so repetition tests nothing; variance would come from
changing the thresholds, which is a new registration.

## What a failure of each prediction would mean

- P2 fails: the proxies or margins are wrong; fix the spec, re-register, re-run. Do not tune on the controls silently.
- P3 fails at the wrong stage: the stage order or a threshold hides the real reason.
- P4 passes: the tie-breaker needs a registered remedy (rank by gap first, or exclude x > 0.95 from the top list). That remedy is run as `funnel v0.2`, not folded into v0.1.

# Registration: soft-mode check on the DFPT-divergent grade-A entries (written before the run)

Registered 2026-10-21 07:05 UTC. Hypothesis: DFPT total dielectric constants above 100 in JARVIS
come from a low-frequency polar mode at the structure's symmetric minimum, which DFPT's
ionic term amplifies as 1/omega^2. If so, the structure is at or near a dynamical instability
and a finite-displacement phonon calculation should show an imaginary (negative) frequency
somewhere in the Brillouin zone, as cubic SrHfO3 does in the literature (octahedral tilts).

Method: phonopy, 0.01 A displacements, supercell chosen so that each lattice vector is at least
8 A, forces from mace-mp-0b3-medium (CPU, float64), frequencies on a 4x4x4 q-mesh plus Gamma.
Reported per structure: the lowest frequency in THz. A frequency below -0.3 THz counts as a
soft mode (the usual numerical-noise band is about +-0.1 to 0.2 THz for a universal potential).

Structures: the five divergent entries (Na2Hf2O5 890, SrHfO3 315 and 295, LuTaO4 277, tetragonal
HfO2 141) and three grade-A controls with ordinary values (Pca21 HfO2 23.8, BaHfO3 34.4, Nd2O3 21.4).

| id | prediction |
| --- | --- |
| P33 | At least 3 of the 5 divergent entries show a mode below -0.3 THz |
| P34 | At most 1 of the 3 controls does |
| P35 | Both SrHfO3 entries are among the soft ones (the tilt instability of cubic SrHfO3 is known) |

If P33 and P34 hold, v0.3 gets a registered rule: a grade-A candidate whose lowest MACE
phonon frequency is below -0.3 THz is demoted to grade B with the flag "DFPT at an unstable
structure"; its true dielectric constant is that of the distorted ground state, which is a
different entry or not in the database.

# Registration: Claude Opus 5.5 on the XRD set (written before any model call)

Registered 2026-10-21 (UTC, after the v0.3 run). No API key was present in the environment when
this was written; no model call has been made. Prompts are frozen in `speclab/prompts.py`;
the runner is `scripts/run_llm_xrd.py`; raw exchanges and usage go to `results/xrd/<run>/raw/`.

## Protocol

- Model `claude-opus-5-5`, adaptive thinking (the model's default), `output_config.effort = "high"`,
  `max_tokens` 16,000, one request per item, SDK retry once on failure, then recorded as silence.
- Two arms, registered together, run in order:
  - **Arm A, reading only:** the observed pattern (1,400 points) and nine CIFs in the prompt; no tools.
  - **Arm B, with a tool:** the same, plus `simulate_pattern(candidate_id)`, which returns the
    candidate's clean simulated pattern on the same grid (no strain, no noise). At most 12 tool
    calls per item. This is the "harness" arm: the model decides what to simulate and compares.
- Order: dry run (count tokens on one item, estimate cost) -> arm A on the public set once ->
  arm B on the public set once -> the better arm on the held-out set three times.
- Launch gate (PRD FR12): on the held-out set, in each of three runs, exact-match rate per tier
  at or above the strain-refined classic baseline measured on the public set (100 / 65 / 50 %),
  and coverage at or above 95 %. Silence counts as coverage, never as an error.
- Budget: hard stop at USD 40 per invocation; expected total for the whole protocol USD 30-60.
- Answer parsing: the last JSON object with a "present" list of one or two ids; anything else is silence.
